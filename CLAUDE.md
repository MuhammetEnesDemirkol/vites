# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Vites, a Claude Code mod that picks the model and reasoning effort for each prompt the person types, with a footer chip to toggle it. Slash command: `/vites aç|kapat|durum|tavan|günlük|rapor`. All user-facing text is Turkish.

It is derived from Model Gear 0.2.3 (MIT, Muhammad Moussa, `muhamoussa7/claude-model-gear`). The design document is `docs/superpowers/specs/2026-11-01-vites-design.md`; it wins over this file on behaviour. The marketplace is `.claude-plugin/marketplace.json` (named `demirkol`), and the plugin lives in `vites/`.

## Commands

There is no build step, no bundler and no installed dependencies. TypeScript is checked and tests are run by the `claude` CLI itself:

```
claude plugin validate vites
claude plugin test vites
```

Tests import from `claude-code/testing`, which only exists under `claude plugin test`, so `node`, `tsc` and `bun test` will not work. `claude plugin test` has no filter option; it runs every `*.test.ts` under the folder.

## Releases

Bump `version` in `vites/.claude-plugin/plugin.json` for every release. Installed copies are cached by version, so an unchanged version can keep the old code in place.

The `vites/.claude-plugin/types/` folder is generated by Claude Code and listed in the root `.gitignore`. Keep it in the working copy so tests run, but do not commit it.

## Plugin layout

- `vites/.claude-plugin/plugin.json` declares name, version and `"types": "./types/index.d.ts"`.
- `vites/.claude-plugin/types/` is generated typings for the `claude-code` host API. Treat it as read-only reference and search it when you need an engine API.
- `vites/hooks/hooks.json` lists `./register.tsx` as the one module.
- `vites/hooks/register.tsx` exports `register: Register` and wires event hooks with `on(...)`. It is engine wiring only; it reads and writes `$.store` and calls the pure modules.
- `vites/hooks/logic.ts` holds the pure functions (parsing, keyword fallback in English and Turkish, gear number, Turkish labels) so they can be tested without an engine.
- `vites/hooks/vites.test.ts` tests `logic.ts` directly and exercises `register` through a mock engine.
- `vites/types/index.d.ts` defines the plugin's own types (`Level`, `Effort`, `Line`, `GearNumber`, `LastPick`, …) and augments `PluginState` in the `claude-code` module. The `atom({ plugin: 'vites', key })` calls in `register.tsx` must use literals that match that interface.

JSX uses a custom factory (`jsxFactory: "h"`). Components are not imported: `$.ui.resolve(e)` returns `Box`, `Text`, `Button` and `Input` for the current surface.

## Conventions

- Every hook handler wraps its work in `try`/`catch` and falls through to `next(e)`, and each `on(...)` ends in `.catch(...)` that does the same. A failure in the mod must never block the person's prompt.
- `$` is only ever passed to functions declared at the top of the file (or imported from the plugin's own files). The validator rejects closures and lookup tables that receive it, so the command router is a `switch`.
- State lives in two places. `atom` plus `read`/`update` (`$.state`) drives the UI. `$.store` persists across sessions and reloads. Writers update both, and `session.start` rehydrates the atoms from the store.
- User-facing strings are short Turkish sentences that say what happened and what was left unchanged. Command arguments are read through `fold()`, so `ac`, `aç` and `on` are the same word.
- Levels are shown to the person as gears: 1 = haiku, 2 = sonnet, 3 = opus, 4 = fable (`gearNumber`). Efforts are shown with `effortTr` (düşük, orta, yüksek, çok yüksek, maks).
- Flags are named `isX`, matching the typings (`isLocked`, `isEnabled`).

## How it works

The flow on `prompt.submit` (`register.tsx` `pickModel`):

1. Skip unless the prompt was typed while idle (`isTypedWhileIdle`), is not a slash command and is not a short acknowledgement (`isShortReply`, English and Turkish words).
2. Ask the smallest model in the install's `model` config row for "level effort" in two words (`askSmallModel`, 4s timeout). If it fails, `guessLevel` and `guessEffort` in `logic.ts` fall back to keyword regexes run on `fold()`ed text.
3. Effort named in the prompt ("ultrathink", "max effort", "yüksek efor") overrides the classifier.
4. `candidatesFor` orders model options for the level and `config.set` tries each until one is accepted.
5. The pick is kept in the `last` atom as a `LastPick` with `gear`, `source` (`classifier` or `keywords`) and `flags`.

Details that need several files to see:

- Models are matched by line name (`haiku`, `sonnet`, `opus`, `fable`) found inside the option string, so new versions work without code changes. Level to line is the `LEVEL_LINE` table.
- The engine has no effort row in `/config`. Effort is injected per request in the `turn.step` hook (`effortToSend`) for the main loop and its subagents alike. It is never saved in settings. Subagents keep their own model. The effort sent is also written to the store under `effort` for the person's status bar, and deleted when Vites turns off. The gear, model and effort of the last prompt are pinned under the prompt with `$.ui.status` (`statusLine`, e.g. `3. vites · opus · yüksek`), cleared when off.
- `applied` in the store is the model Vites last set. A hand `/model` or `config.set` from the composer turns the plugin off without restoring, and a toast says why. A model that differs on the next prompt without such a call (seen after `/compact`, or from another window sharing the setting) does not turn it off; it sorts the prompt again. A bare `/effort` counts only if the saved effort actually changed, since the menu can be cancelled.
- Turning on saves the current model as `previous`. Turning off through the command or the chip restores it via `restoreValue`.

Store keys: `enabled`, `previous`, `applied`, `effort`, plus `ceiling`, `gear`, `journal`, `usage` from the spec's later sections (see the design document).
