## Shared types (owned by Task 1, used by all)

`vites/types/index.d.ts`:

```ts
export type Level = 'small' | 'everyday' | 'strong' | 'strongest'
export type Effort = 'low' | 'medium' | 'high' | 'xhigh' | 'max'
export type Line = 'haiku' | 'sonnet' | 'opus' | 'fable'
export type GearNumber = 1 | 2 | 3 | 4
export type PickSource = 'classifier' | 'keywords' | 'tag'
export type PickFlag = 'capped' | 'held' | 'dropped' | 'tagged'
export type LastPick = {
  level: Level; effort: Effort; model: string; isGuess: boolean
  gear: GearNumber; source: PickSource; flags: PickFlag[]
}
declare module 'claude-code' {
  interface PluginState { vites: { enabled: boolean; last: LastPick | null } }
}
```

Store keys (`$.store`): `enabled` boolean · `previous` string · `applied` string · `effort` Effort · `ceiling` `Line | 'yok'` (absent = `'opus'`) · `gear` GearState (Task 2) · `journal` JournalEntry[] (Task 3) · `usage` UsageBook (Task 3).

## Review Focus

1. A prompt that is only tags (`#opus`) or tags + whitespace → model switches, text sent is empty-safe (if stripping would leave an empty prompt, send the original text unchanged).
2. `/vites tavan haiku` while a tag-held fable is active → tag hold stays until it drops; next automatic upgrade is capped at haiku.
3. `turn.step` with `usage: null` (the mocks return this) or a model string with no known line (`claude-x-1`) → nothing recorded, no throw.
4. Journal/usage store read returns a non-array / garbage (older or corrupted store) → treated as empty, overwritten cleanly.
5. Store write fails during `pickModel` → the model switch already made stays, prompt goes through, no unhandled rejection.

Each item has a test in the owning task below.
